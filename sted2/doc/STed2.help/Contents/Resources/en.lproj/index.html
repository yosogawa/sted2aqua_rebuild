STed2 plus for Mac — Restoration & Feature Expansion

STed2 plus for Mac is a port of the classic MIDI sequencer "STed2"—originally designed for the Sharp X68000 series—to macOS. It also includes several enhancements beyond the original feature set. To distinguish it from the original version, it is referred to as the "STed2 plus" version.

The Origins of This Software

The original STed2 was created by the late Takayuki Toda (known as TURBO). Mr. Toda passed away in 1997 at the age of 27. Subsequently, thanks to the efforts of his family and various volunteers, the source code for his works—including STed2—was made publicly available.

「STED2 最終版のソース公開にあたって --- 追悼の言葉と皆様へのお願い」（ゆい工房 山本裕一郎氏）
Yuichiro Yamamoto, Yui Kobo: “On releasing the source of the final STed2 — words in memory of the author, and a request.”

Based on this source code, Daisuke Nagano created a port for the UNIX & X Window System, which was subsequently used by Toshi Nagata to develop a version for Mac OS X (PPC & i386). Nagata’s final version is archived in a digital archive repository on GitHub, maintained by Misty De Méo: https://github.com/mistydemeo/sted2aqua. I, Ogawa, have created a fork of this repository. My work includes restoring and implementing features present in the original Human68k version that were missing from the Mac version, as well as adding enhancements necessary for a modern-day DTM (desktop music) application. This software holds a significant place in the history of Japanese electronic music, in the practice of sequencer programming known as “uchikomi.” My goal is to ensure it does not remain buried in a digital archive—nor require the cumbersome setup of a Human68k emulator just to use the original TURBO version. Instead, I aim to restore and revive it, making it an accessible, functional "vintage tool" that anyone can easily download and use.

Details and feature enhancements for the Plus version

  • Compatible with macOS 12 Monterey or later. It supports both Intel 64-bit and Apple Silicon architectures. The minimum system requirements are: macOS 12 Monterey, 4GB of RAM, a display resolution of 1366x768, and a Core i5 processor. It has been verified to work on a MacBook Air A1465 (11-inch, Early 2015). It should also run without any issues on Macs equipped with Apple Silicon.
  • Using modern AI-driven analysis, we conducted a thorough process of identifying, tracking, and eliminating vulnerabilities. Key measures included standardizing variable sizes—primarily by replacing numerous `long` types in the C source code with `int32_t`—and modifying memory-copy functions (which are prone to causing buffer overflows) to incorporate safeguards that limit the number of bytes copied. Furthermore, as file systems have evolved, the maximum length for file paths has increased; we identified and expanded several long-neglected arrays—dating back to the Human68k era—that had hard-coded, overly restrictive path size limits. Such an undertaking would have been impossible to analyze without the aid of AI.
  • The "Internal Synth" originally implemented by Mr. Nagata—which utilizes the Apple DLS Music Device—has been renamed "Apple DLS Synth" to distinguish it from another synthesizer mentioned later. Additionally, I (Ogawa) have added a menu option that allows users to load arbitrary DLS files or SoundFonts (in the `.sf2` format).
  • As a second synthesizer option, we have integrated the open-source AMY synthesizer, which can be loaded in place of one of the two available DLS synth instances. It includes presets compatible with the DX7, as well as virtual-analog presets modeled after the JUNO-6/106. Given its multi-timbral capabilities, it has the potential to serve as a substitute for units like the TX816 or MKS-7; however, because it is an open-source project that is still maturing—and due to some unique quirks in its system integration—support is currently limited to preset selection. We plan to expand this functionality in the future.
  • I have connected three mastering-oriented effects in series following the stereo mix of the two synthesizers: an EQ (high/low), a reverb, and a limiter. This setup is particularly useful, as some SoundFonts have inconsistent volume levels that can be harsh to the ears. You can also bypass the entire effects chain if you prefer.
  • Regarding the MIDI functionality issues in the previous Mac version, I have gone through and verified each feature one by one. I have also added real-time updates—such as those in the EDIT screen—that synchronize with playback, a feature that was previously missing. I believe the software’s behavior is now much closer to that of Recomposer.
  • Following a layout change to the main screen, I have added a locator in the space previously occupied by the credits and implemented transport controls; this includes support for MIDI Timing Clock and Song Position Pointer.
  • I have continued work on features that TURBO had begun implementing. This includes support for MIDI SYNC EXT (allowing for slave operation), the addition of function key labels for the "one-touch ST/GT" feature, and the inclusion of SYNC/THRU mode settings in the blank lines on the main screen.
  • I have updated the supported sound-module specifications, which had remained at the level of mid-1990s Roland products. The update adds bank select for the GM1, GM2, and XG standards. GM1 is the default setup for the SoundFont player. A module define file for each of these standards is included. A module define file is also included for the SAM2695 chip from DREAM—a manufacturer that continues to produce GM (GS)-compatible chips to this day, which remain popular in the hobbyist hardware and DIY electronics communities.
  • Since collecting SoundFonts without an accompanying patch list makes selecting instrument sounds in STed2 difficult, I have added a new menu command that parses SF2 files and automatically generates STed2 module define files. By placing these generated files in the designated `deffile` folder, you can load them for each MIDI A/B port using the "UNIT SEL" function. This feature utilizes the open-source TinySoundFont package as an SF2 file parser.
  • The Apple DLS synthesizer is designed to ignore all incoming System Exclusive (SysEx) messages. Since some musical pieces rely on commands such as "GM System On," "GS Reset," "GM2 System On," or "XG System On" to reset the sound engine, failing to process these would leave the previous song’s instrument balance in place, so playback is inconsistent. To address this, we implemented an external MIDI message-parsing layer that specifically detects these reset commands and translates them into equivalent Control Change messages that the DLS synthesizer can interpret, thereby ensuring the sound engine is reset correctly.
  • In macOS, switching the output device via "Sound" or "Audio MIDI Setup" triggers an initialization of the internal sound engine, as per the specifications of `AVAudioEngine`. STed2 is designed to respond to notifications of such device changes; if a song is playing, it will stop playback and rewind to the beginning of the song.
  • The font has been updated, and a font panel has been added. The default font is "KH-Dot-Kodenmacho-16"—a typeface with ties to the X68000—which is included as a TTF file within the application bundle. Upon launch, if this font is not already present on the macOS system, it will be installed automatically. You may also replace it with a different monospaced font if you prefer.
  • A color panel has been added. You can invoke the standard macOS color panel to adjust colors—with changes reflected immediately on the STed screen—and then save only the final settings to `sted2.cnf`. Up to five configuration sets can be stored in the Preferences. Additionally, the classic, traditional STed color scheme is included as a default option.
  • I have added a Keyboard Viewer window. Since the X68000 keyboard is being emulated, certain keys—which do not exist on a standard macOS keyboard—are mapped to substitutes via the `#key_` fields in `sted2.cnf`; this window provides a visual representation of those mappings. When you press the Control or Option keys on your Mac, the display updates accordingly, changing both the key colors and the labels shown on the keycaps.
  • We have added a "Command Cheat Sheet" window. It displays only the keyboard shortcuts for the current screen, and those used when entering a Special controller, out of the many shortcuts in STed. You no longer need to keep going back to the full documentation.
  • The display can be enlarged by changing the NSView scale factor in macOS. An interpolation algorithm is chosen for that scale, so the picture stays as sharp as possible.
  • Mouse scroll events are supported (including two-finger scrolling on Mac touchpads and using a mouse scroll wheel). These actions are currently mapped to the UP/DOWN key codes, allowing them to be used in the Edit screen, when selecting main functions, and when navigating lists of instrument sounds (patches).
  • In addition to RCP, R36, and MID formats, the file import/export feature now supports the ABC notation format. This format is widely used in tools such as the music-generation AI "YuE2" and the "music21" library. Furthermore, it is a format that general-purpose generative AIs (like Gemini, ChatGPT, and Grok) can produce when asked to compose music; you can simply save the AI's output as a text file with an ".abc" extension to import it. The system can export scores that include multiple tracks and GM-compliant instrument mappings.

    • Future Roadmap

    • Short-term goal: Our immediate objective is to squash the major bugs in the current macOS version and release an initial, fully functional version—a revived and expanded iteration of the sequencer that is ready for practical use.
    • Medium- to long-term goals: Once the core macOS version is stabilized, I plan to port the application to the SDL3 framework—which utilizes a GPU-based renderer—to further enhance the smooth, responsive performance characteristic of STed2. Since this framework also serves as a hardware abstraction layer, it will facilitate the replacement of macOS-specific code—starting with rendering, and extending to keyboard input, timers, threading, and audio systems. Once the dependency on macOS is largely eliminated, the path will be open for porting to other operating systems. The next target is Windows. Following a successful port there, I intend to explore Linux, Android, and ChromeOS. Looking further ahead, I hope to extend support to embedded environments, such as the ESP32 microcontroller—a platform rumored to be compatible with SDL3.
